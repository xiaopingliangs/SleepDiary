# Clinician Bridge：本地医生摘要与人工指令

`ARCH-FULL-0.1` 工程草案，2026-09-11。关联 [总览](FULL_APP_ARCHITECTURE.md)、[数据与迁移](FULL_APP_DATA_AND_MIGRATION.md)、[统一知识](KNOWLEDGE_AND_EVIDENCE_ARCHITECTURE.md)。本轮不实现导出新格式、药物建议或 clinician override。

## 1. 目标与边界

医生/治疗师介入是治疗流程的一部分。App 整理实际记录与待确认问题，不出诊断，不把“需要临床 review”写成失败。离线无账号模式不能仅凭一个姓名核验对方确实为医生，也不能把用户转述当成已认证临床指令。

现有日记 PNG 保持不含 comment/Safety。下面是独立的医生摘要用途，使用独立 DTO、预览和主动同意；不会修改日记分享白名单。

## 2. 摘要数据和生成链路

用户选择时间范围 → 展示各类数据及缺失 → 选择披露内容 → 预览整份摘要 → 本机展示，或明确导出/分享。默认最少数据；备注、安全、药物、心理/共病情境及认知自由文本分别选择，不与“选择日记”隐式捆绑。

| 摘要部分 | 内容和来源 |
|---|---|
| 基本上下文 | 所选日期范围、生成时间、数据完整性；默认无需身份信息 |
| 原始日记 | 选择范围的主观估计及用户选择的备注；来源 Diary ID/版本，缺日不填零 |
| 疗程 | 当前阶段、治疗方式、协议/规则版本、治疗周、计划 revision |
| 当前计划 | 经验证的 prescribed TIB、固定起床、最早允许上床、有效时段/时区；与实际 Diary TIB 分开 |
| Review | 经审核的指标、样本范围、依从反馈、缺项、保持/调整/暂停的历史理由 |
| 安全与情境 | 明确选中的 daytime sleepiness、Safety facts/flags、药物变化、疼痛/共病自报、Exception 事件 |
| 待确认问题 | 从有效规则/知识节点生成的问题、尚缺信息和 App 无法自动处理的点 |
| 追溯 | rule IDs、来源、内容复核日期、人工指令及其核验状态（按选择披露） |

没有治疗数据时不生成假 TIB、治疗周或“正常”结论。用户自报的诊断名称标为“用户报告/尚未核验”，不能经摘要渲染变成 App 诊断。数据窗口以生成快照为准，导出中途编辑不产生混合时点内容。

建议先实现可离线展示的摘要，再增加用于就诊阅读的 PDF；以后如需结构化医生交换 JSON，使用不同的 artifactType/schema，不能误进入完整备份恢复器。实际格式与许可/渲染依赖在实施阶段固定，本轮不添加依赖。

## 3. 人工指令模型与审核

`ClinicianDirective` 至少保存：ID、原文、录入时间、声称的临床提供者、实际录入者、原因、原 Protocol state/plan 引用、作用范围、有效期、核验状态、结构化意图、来源说明、supersedes/revoked 关系。

工作流：

1. 用户/临床人员录入意见原文和来源；显示“谁实际输入”与“声称来自谁”。不需要创建云账号。
2. 将结构化意图与原文并排核对。使用明确字段操作，不能 NLP/LLM 自动提取后执行，更不能执行粘贴文本中的指令。
3. 核验身份/来源、允许覆写范围和生效条件；离线可信身份流程尚需项目临床治理确认。未经核验可保存为沟通记录，不能自行解锁治疗。
4. 以当前 Safety 和协议兼容检查验证；冲突或越界则显示需进一步确认，不通过一个 `override=true` 清空限制。
5. 获准后由同一决策引擎产生新的 plan revision；保留旧计划、原意见、理由和当时输入。医生意见不修改原始 Diary。
6. 修订/撤销另记新事件；到期后按已审核规则重评，不能默认恢复此前窗口。

允许人工改变哪些参数、哪些安全限制能在何种临床参与条件下调整、复核期限，以及用户转述意见是否在特定模式下有任何执行权限，均列入医学/治理待确认项。工程架构不替人授予临床权力。

## 4. 导出与隐私

摘要保存在私有缓存，实际导出用 SAF，分享用 FileProvider content URI 与临时读权限；用户确认前不创建公共文件或发给第三方。显示已启动系统分享不等于证明医生收到或阅读，审计只记实际完成的本机动作。

缓存清理策略与可分享 URI 有效期要兼顾接收方读取；失败不强杀进程。敏感正文不进入日志，审核记录不需要保留文件路径中的个人名字。用户可取消或缩小选择，历史原始数据不因取消摘要而变化。

完整备份保留需要恢复的 ClinicianDirective 及审计关系；恢复的历史指令不自动重新获得当前执行权，须重新检查有效性。哈希只验证内容一致性，不认证医生身份。

## 5. 测试与验收

- 空 Diary/无治疗/部分周期/旧协议/缺包都有真实空状态，不产生假结论。
- 数据来源及每次生成快照固定，TIB 观察值与计划值不混淆，版本与原决定一致。
- comment/Safety/药物等未选时不进入 PDF、分享正文、缓存 DTO 或模板；既有 PNG 继续排除全部这些内容。
- 取消、SAF 错误、接收 App 失败、Activity 重建不出现“已发送给医生”的伪结果。
- 用户转述、过期、撤销、冲突、未知作者意见不能绕开安全检查；修改意见不丢原内容/原 state。
- 备份恢复后完整历史保留，但执行须经过本机激活检查与适用性复核。
- 最终就诊摘要的可读性与问题清单由实际临床使用者审核；自动化测试不替代此审核。
