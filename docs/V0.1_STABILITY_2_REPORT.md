## 备注调查与修复

检查了 DiaryScreen → 输入回调 → DiaryViewModel.comment/updateForm → SavedStateHandle/DiaryForm → RoomDiaryUiStore → DiaryRepository.save → Room 按 UUID 回读，以及 DiaryForm.from 的编辑预载路径。

数据库链路原样保存 comment，事务内外都比较整条实体；未发现保存时清空备注的逻辑。原备注控件是 AndroidView 内的 EditText，原生 IME、TextWatcher、Compose update 和表单值之间存在双向同步。上一轮仅限制 setText 的触发，用户真机仍无法输入，说明该桥接方案未解决现场问题。当前无连接设备，不能把此前推测的旧值覆盖宣称为已复现的唯一根因。

新增 CommentTextInput，使用标准 Material 3 OutlinedTextField。文本值由 FormState/ViewModel 持有，onValueChange 立即更新表单和 SavedStateHandle；输入法组合状态与选择范围交给标准 Compose 控件处理，不再自行 setText 或维护另一份备注文本。

备注输入路径已彻底移除 AndroidView(EditText)。项目整体仍保留原有数字备用输入和 Safety“其他名称”的原生控件；它们未纳入本轮改写。曾尝试替换共用控件，但数字弹窗测试发生布局超时，因此撤回该连带改动，保留原数字控件和全部原测试。本轮没有以删除测试、跳过测试或延长超时换取通过。

主页面保持“＋ 昨晚有特殊情况（可选）”，默认折叠。展开后只有短说明和自由文本框，不新增任何分类或医学选项。已有备注由表单预载，展开即可编辑。清空后保留现有允许的空字符串语义；数据库也继续支持 null。CSV/JSON 序列化、数据库和分享实现均未更改，PNG 继续不含 comment。

## 设置返回

- 查看当前安全问询、重新完成问询、继续 DRAFT：显示顶部“← 返回设置”，系统返回执行相同行为。
- 从设置进入后触发的安全帮助页和完成结果页：同样提供返回设置；保存期间暂不允许离开，避免与正在提交的事务竞态。
- 用 safetyFromSettings 和 safetyPage 记录导航来源及当前页，并保存在 SavedStateHandle。首次 onboarding 的 Safety 不带设置来源，不显示“返回设置”。这些是暂存 UI 状态，不是备份关键业务字段。
- 返回时只回读当前 SafetyAssessment，不删除答案、不改变 DRAFT 或分流。尚未提交的当前选项可放弃，已经提交的答案继续从 Room 加载。
- 历史记录的编辑页新增“← 返回历史记录”，保留原历史日期页面；成功保存仍进入原保存成功/周总结流程。
- 历史、隐私、方法、术语、版本原有返回路径均经过回归检查；方法 → 术语 → 返回会回到方法页。
- 导出说明使用取消，恢复摘要使用取消，结果提示使用关闭；系统 SAF 继续使用系统自己的返回/取消，不加伪造返回键。
